## 1. Summary

Aura is a Tauri 2 and React glass shell. Before this follow-up it already had a cursor-monitor fullscreen window, suggestions from rules then history (up to 8, with no catalog padding), a scratchpad quick note, edit-mode layout in `%LOCALAPPDATA%\aura\layout.json`, a widget-state file, and a real window switcher (`list_windows`, `capture_window`, `activate_window`, `close_window`). That base was unit-tested and compile-checked. It was not watched on a live window.

This follow-up adds eight behaviours on that base:

1. The navigation panel is the sidebar. One switch hides it with `panels.nav.visible`.
2. Open windows sit in one horizontal overlapping stack, laid out by `layoutStack`.
3. A preload thread captures dirty windows while the HUD is still hidden.
4. One selection index drives the stack. Older selection tokens are dropped.
5. A Shortcuts widget can be added more than once. It is absent from the default and reset layouts.
6. Removing a widget asks Keep, Delete, or Cancel, and Keep leaves the saved blob.
7. Fullscreen acrylic is gone. Blur is clipped to an inset rounded sheet.
8. A rule miss publishes the history card immediately. A failed model attempt is remembered, and diagnostics ride the existing snapshot.

The automated checks that assert those rules passed. The running window, the blur region, preview pixels, widget dialogs, and a live model call were not observed.

## 3. Feature implementation

### Earlier base

The shell, suggestion ranking, scratchpad, layout file, widget-state file, and window commands were already in place. Suggestions come from rules, then history, and stop at 8. The catalog is not used to pad that list. That base was unit-tested and compile-checked. It was not watched on a live window, and this follow-up did not open one either.

### Sidebar

The navigation panel is the sidebar. Visibility is the boolean `panels.nav.visible` in the layout document (`hud/src/layout/document.ts`, `hud/src/layout/types.ts`). One switch at the top of the panel sets that flag. Other panels still minimise and hide on their own controls.

When the flag is false, `hud/src/layout/sidebar.ts` picks the nearest horizontal edge and `hud/src/components/PanelFrame.tsx` translates the panel past that edge. A “Show sidebar” handle stays on screen. Legacy `minimised` and `hidden` load as `visible: false`. Position and z are kept. The slide duration in code is 280ms unless animations are off or reduced motion is requested, in which case the transition is `none`.

Checked by `npx tsx src/layout/navVisibility.test.ts`, which passed, and by `tsc`, which passed. The slide was not watched on a live window.

### Horizontal window stack

The stack is one overlapping row, not a carousel. `layoutStack` in `hud/src/windows/stackLayout.ts` places each card origin 20% of the card width past the previous card (`STEP_RATIO = 0.2`) and translates the row so the selected card is centred. Neighbours overlap. Card size shrinks with the count down to 140×88, then the row scrolls horizontally. A container smaller than that floor shrinks the floor to fit.

`hud/src/components/WindowStack.tsx` uses that layout. Hover leaves the selection index unchanged and draws a light outline on a card that is not selected. Click calls `activate_window`. Wheel, drag, and Left/Right change the selection index only. The selected card uses a stronger border, higher brightness, and scale `1.06` (`SELECTED_SCALE`).

Checked by `npx tsx src/windows/stackLayout.test.ts`, which passed, and by `tsc`, which passed. The live stack was not opened.

### Previews

`preview_preload_loop` starts from Tauri `setup` in `hud/src-tauri/src/lib.rs` while the main window is still hidden (`visible: false` in `tauri.conf.json`). Each pass lists windows, computes dirty hwnds, and captures with at most two workers (`hwnds.len().min(2)`).

`dirty_windows` in `hud/src-tauri/src/window_switcher.rs`, mirrored by `dirtyWindows` in `hud/src/windows/previewFreshness.ts`, recaptures a hwnd when it is new, when its title changes, or when it becomes the foreground. A hwnd that left the list is not captured. The same list and the same foreground produce an empty dirty set. The preview cache limit is 40 (`PREVIEW_CACHE_LIMIT`). A capture failure stays sticky until the title changes or that hwnd becomes foreground.

The placeholder in `hud/src/App.css` uses `pointer-events: none`, so it does not move the selection. Preview images use `object-fit: contain`.

Checked by `npx tsx src/windows/previewFreshness.test.ts`, which passed, and by `tsc` and `cargo check`, which passed. The preload thread was not watched on a desktop. No capture was observed.

### Motion

There is one selection index. `commitIndexBurst` and `replaceSelection` in `hud/src/windows/stackMotion.ts` apply indexes in order and keep the latest token, so an older burst cannot overwrite a newer one. The preview and the title follow that index. Hover is an outline on an unselected card. The selected card is the one at scale 1.06.

The card transition in `hud/src/App.css` is one 300ms CSS transform (with matching opacity, filter, border, background, and shadow). A new index replaces the transform target. The layout function returns a new result and does not queue animations.

Checked by `npx tsx src/windows/stackMotion.test.ts` and the stack layout tests, which passed, and by `tsc`, which passed. Motion was not watched live.

### Shortcut widget

The shortcut picker is gone from the nav. The widget is registered with `allowMultiple: true` in `hud/src/widgets/registry.ts` and is rendered by `hud/src/widgets/ShortcutWidget.tsx`. It is not placed by the default layout or by reset. Ids and the size variant live in `%LOCALAPPDATA%\aura\widget-state.json` under the instance id.

Suggestions offered for a shortcut are snapshot action kinds only. A manual add uses `list_catalog`. Launch calls `open_action` with `{ kind }` only while edit mode is off. Sizes in `hud/src/widgets/shortcuts.ts` are compact 288×192, regular 360×216, and wide 480×192.

Checked by `npx tsx src/widgets/shortcuts.test.ts`, which passed, and by `tsc`, which passed. The library and launch were not exercised in the HUD.

### Library removal

Remove asks Keep, Delete, or Cancel (`hud/src/components/DashboardStage.tsx`, policy in `hud/src/widgets/library.ts`). Keep drops the layout entry and leaves the blob. Delete drops the layout entry and the blob. Cancel leaves both. Restoring a kept id puts that same id back on the stage and does not rewrite the blob.

The library still lists Shortcuts when instances exist. Add stays available because the widget is `allowMultiple`. There is no disabled “Added” state. The library preview labels are the constants One, Two, Three, and Four.

Checked by `npx tsx src/widgets/library.test.ts` and the shortcuts tests, which passed, and by `tsc`, which passed. The dialog was not clicked in the HUD.

### Rounded glass

`hud/src-tauri/tauri.conf.json` no longer sets fullscreen `windowEffects` acrylic. On show and on fit, `hud/src-tauri/src/lib.rs` calls `glass::apply_glass_blur`. That sets the DWM system backdrop to `DWMSBT_NONE`, builds a rounded region with `CreateRoundRectRgn`, and calls `DwmEnableBlurBehindWindow` with `DWM_BB_ENABLE | DWM_BB_BLURREGION`. A failed region is not replaced with a full-window blur.

Margin is 32 CSS pixels and radius is 28 CSS pixels, multiplied by the window scale factor (`GLASS_MARGIN_CSS`, `GLASS_RADIUS_CSS` in `hud/src-tauri/src/glass.rs`). The same CSS sizes are the inset on `.glass-sheet` in `hud/src/App.css`. Tint is on `.glass-sheet` only. `glass_sheet` is pure inset math and does not touch a window.

The window still covers the monitor, including the taskbar rectangle. Aura does not hide the taskbar. `ShowWindow` in `window_switcher.rs` is `SW_RESTORE` on a minimized target window during activate. It is not a taskbar hide. The clear margin can show the taskbar. Clicks in that margin still hit Aura, because the margin is part of this window and is not click-through.

Checked by `cargo test glass_sheet`, 3 tests passed, covering inset math at 1920×1080, 2560×1440, 1366×768, and 3440×1440, a positive sheet on the short monitor, and radius clamped to half the shorter side. `cargo check` and `tsc` passed. The blur was not watched live.

### AI

On a rule miss, `bridge/watch.py` publishes the history card before the model returns. The Godot suggestion on 7 November was that history card. It was not a model answer.

`post_chat` in `bridge/model.py` raises `ModelError` on HTTP failure, timeout, a body that is not JSON, and a body that is not a chat completion. The API key is present. Its length is 164. The key is not repeated in this report, and `aura.secrets.json` was not opened for it. The advisor does start.

Previously a `ModelError` left the history card in place and did not remember the attempt, so the same context could be sent again. `consider` now remembers the attempt per context fingerprint. A later failure keeps the last successful catalog id. The remembered attempt stops the restart loop. The in-memory attempt cache drops the oldest entry past 20.

`hud.shown` on the existing actions pipe calls `consider` once and does not launch a catalog action, including when a `kind` is also present. Diagnostics are `payload.diagnostics` on the existing snapshot from `bridge/state_snapshot.py`. Settings opens the stage list (`ModelDiagnosticsPanel`). Suggestions show one error line from `modelStatusLine`.

Checked by the unittest command in section 5, which ended `OK` (51 tests), and by `npx tsx src/modelDiagnostics.test.ts`, which passed. `tsc` and `cargo check` passed. No live OpenAI call was made. The 7 November HTTP status code was not reproduced.

## 4. Technical decisions

The sidebar reuses the nav panel and stores one boolean. Legacy minimised and hidden become `visible: false` on load, so old layout files do not grow a second visibility field. Other panels keep their own minimise and hide behaviour. The slide is a CSS transform toward the nearest horizontal edge, so a second toggle before the 280ms transition finishes reverses the same transform. Reduced motion and animations-off skip the slide.

The window switcher stays a stack. `layoutStack` is a pure function of count, selected index, and container size. Overlap is a fixed 20% step. Below the 140×88 floor the row scrolls instead of shrinking further, except when the container itself is smaller than the floor. Selection is an index, not a hover target. `commitIndexBurst` folds a burst down to the last index so a slow preview cannot drag the title back to an older card. The 300ms card transition is one CSS transform that the browser retargets when the index changes.

Preview work stays in the Tauri process. The preload loop polls every 1500ms, starts during setup, and limits in-flight captures to two. Dirty detection is shared in spirit by Rust (`dirty_windows`) and TypeScript (`dirtyWindows`): new hwnd, title change, or a new foreground hwnd that is actually in the list. Failures stick so a broken hwnd is not retried on every poll. The cache holds about 40 previews. Placeholders do not receive pointer events.

Shortcuts are data on the widget-state file, keyed by instance id, with the variant stored beside the ids. `allowMultiple` is why the library can add another Shortcuts widget and why Add does not become a disabled Added state. Reset removes the layout entries and leaves the blobs, which is the same Keep rule as library removal. Launch stays `open_action` with a kind, and only outside edit mode. The library preview does not read the saved shortcut ids; it shows One, Two, Three, Four.

Glass moved from Tauri’s fullscreen acrylic effect to an in-process DWM blur region. Backdrop is forced to none so the old full-window material does not remain. The region is inset by the same 32/28 CSS pair the stylesheet uses, converted to physical pixels with the scale factor. Radius is clamped to half the shorter sheet side. The margin is transparent on purpose and still belongs to the Aura window, which is why the taskbar can show through it and why clicks there still hit Aura. The taskbar is not hidden.

The model path publishes the history suggestion first, then asks the model. A fingerprint of the context remembers a finished attempt, success or failure. Failure does not clear the last successful catalog id and does not schedule another send of that same fingerprint. Diagnostics are a field on the snapshot the HUD already receives. They carry stage status, lengths, and whether a key is present. They do not carry the key, note text, or clipboard text.

No second process, FastAPI service, or startup command was added. See section 8.

## 6. AI diagnostics

A rule miss still shows a suggestion immediately. `bridge/watch.py` publishes the history card, then the advisor may replace it. The 7 November Godot card was that history card.

`post_chat` raises `ModelError` for an HTTP error, a timeout, a host that does not answer, a non-JSON body (`responseRetrieval`), and a body that is not a chat completion (`responseRetrieval`). The advisor starts. The key is present and its length is 164. The key is not written here.

`consider` fingerprints the context and stores the finished attempt. A repeated fingerprint is not sent again. If a later context fails, the last successful catalog id remains the suggestion. That is the change from the earlier behaviour, where a `ModelError` left the history card and forgot the attempt.

Diagnostics use the stages in `bridge/model.py` and `hud/src/modelDiagnostics.ts`: initialisation, availability, request generation, context supplied, request delivery, inference completion, response retrieval, recommendation ranking, frontend delivery, and last error. Context supplied reports lengths and flags (`noteLength`, `clipboardLength`, whether a window title is present, process name, history counts). It does not report note text, clipboard text, or the key. Availability reports `keyPresent`, host, and model name.

`bridge/state_snapshot.py` copies that object onto `payload.diagnostics`. The HUD reads it in `hud/src/App.tsx`. Settings opens `hud/src/components/ModelDiagnosticsPanel.tsx`, which lists every stage through `diagnosticRows`. `modelStatusLine` feeds Suggestions a single error line when the last attempt failed or the model is off.

`notify_hud_shown` writes `{"protocol":"aura","type":"hud.shown"}` on the existing actions pipe. `accept_action` treats that type as consider-once. A `kind` on the same message does not launch.

The failure path and the snapshot shape were tested with a fake transport and passed. A successful live model response was not verified.

## 8. Architectural changes

The process model is unchanged. There is no second process, no FastAPI service, and no startup change. The taskbar is not hidden with `ShowWindow`.

The additions are in-process:

- `hud.shown` is a new message type on the existing actions pipe. The watcher already reads that pipe. The message runs `consider` once and does not launch.
- `diagnostics` is a new field on the existing state snapshot. The HUD already consumes that snapshot.
- Fullscreen acrylic in `tauri.conf.json` is replaced by a Win32 blur region in `hud/src-tauri/src/glass.rs`, applied from the existing show and fit path in `lib.rs`. `Win32_Graphics_Gdi` was added in `Cargo.toml` for `CreateRoundRectRgn`.

Layout and widget state stay in the same local files: `%LOCALAPPDATA%\aura\layout.json` and `%LOCALAPPDATA%\aura\widget-state.json`. Window commands stay the existing `list_windows`, `capture_window`, `activate_window`, and `close_window` commands, with preload and dirty capture added beside them.
